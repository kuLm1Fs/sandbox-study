# Phase 2 错题本

> 只收实机真实踩过的。每条：**看到什么 → 为什么 → 怎么修**。来源：2-1 ~ 2-5 实机提交记录与命令记录。

## 1. seccomp 装早了，把自己的初始化也挡掉

- **看到什么**：容器起不来，报错 `把 / 设为私有: operation not permitted`。
- **为什么**：seccomp 过滤器一旦装上就不可逆。过滤器装在 `pivot_root` 之前，容器初始化时自己的那几次 `mount` 也被黑名单挡掉了。
- **怎么修**：过滤器装在 `child()` 的最后一步——`pivot_root` 之后、`execve` 之前。
- **教训**：不可逆的操作放最后；初始化和业务用不同的权限阶段。

## 2. seccomp 在 Go 里没生效 / 行为诡异

- **看到什么**：过滤器装了，容器里被禁的 syscall 还是能调。
- **为什么**：seccomp 过滤器是**每线程**的；Go 的 goroutine 会在系统线程间漂移，装过滤器的线程和最后 `execve` 的线程可能不是同一个。
- **怎么修**：`child()` 开头 `runtime.LockOSThread()`，把当前 goroutine 钉在当前系统线程上。
- **教训**：跟内核打交道的 Go 代码，凡是"per-thread"语义（seccomp、namespace 也是）先想 `LockOSThread`。

## 3. `cg()` 在 chroot 之后调，cgroup 建到了容器里

- **看到什么**：cgroup 限额没生效，或 `/sys/fs/cgroup` 路径解析异常。
- **为什么**：`chroot` 之后，`/sys/fs/cgroup` 会在容器的新根里解析——根本不是宿主机的 cgroupfs。
- **怎么修**：由父进程在 `clone` **之前**建 cgroup，再用宿主机视角的 PID 把子进程放进去。
- **教训**：namespace 只能在创建进程那一刻设置；cgroup 这类"宿主机视角"的操作，永远在换根之前由父进程做。

## 4. 教程的占位符直接抄，跑不起来

- **看到什么**：`Mount("thing", "mytemp", "tepfs")` 之类的调用行为异常；chroot 进了教程作者的 `/home/liz/ubuntufs`。
- **为什么**：教程代码里的三个参数全是占位符；chroot 目标是作者自己机器的路径。
- **怎么修**：占位符 mount 直接删掉（`/proc` 才是必需的）；chroot 目标改为从父进程传入的真实 rootfs；`/proc/self/exe` 少了开头的 `/` 会按 cwd 相对解析，补上。
- **教训**：教程代码先读懂再抄，占位符和作者本地路径是两类最常见的"抄坑"。

## 5. 容器挂载传播回宿主机

- **看到什么**：容器里的 mount 操作影响到了宿主机（隔离缺陷）。
- **为什么**：新 mount namespace 会继承父级的传播类型，默认可能是 shared。
- **怎么修**：补 `MS_PRIVATE`，把新 namespace 的挂载设为私有。
- **教训**：`chroot` 不卸旧根，不是安全边界——要 `pivot_root` + 卸载旧根；再补 `CLONE_NEWIPC` / `CLONE_NEWNET`。

## 6. `go build` 在仓库里产出同名二进制

- **看到什么**：`git status` 里冒出一个 `phase-2` 的二进制文件。
- **为什么**：在 `phase-2-container-v2/` 下直接 `go build`，产物默认落在当前目录，文件名跟目录同名。
- **怎么修**：`.gitignore` 忽略；构建时显式 `-o work/`（`work/` 本来就是 git 忽略的实验区）。
- **教训**：`impl/` 只放源码，二进制一律进 `work/`。

## 7. NAT 规则的 `-o` 填成了内网口，容器上不了网

- **看到什么**：容器 `ping 8.8.8.8` 一直卡住（不是立刻报错）；`iptables -t nat -L POSTROUTING -n -v` 里那条规则 **`pkts=0`**。
- **为什么**：`-o` 表示"包从哪张网卡**出去**"。容器去公网是从宿主机的 `ens5` 出去的，写 `-o veth-h` 是反向的，条件永远匹配不上。
- **怎么修**：`-o` 换成默认路由的网卡。代码里用 `defaultIface()` 从 `ip -o route show default` 解析，**不硬编码 ens5/eth0**（每台机器不一样）。
- **教训**：**iptables 规则存在但 `pkts=0` = 条件从没匹配过**，先怀疑接口名/源地址/方向，别急着怀疑别处。

## 8. 把 `veth-h@if5` 当成网卡名

- **看到什么**：复制 `ip -brief addr` 的输出去填 `-o`，结果规则永远不生效。
- **为什么**：`@ifN` 是 `ip` 的**显示装饰**（提示对端接口的 ifindex），不是接口名的一部分。
- **怎么修**：填 `veth-h`。想确认对端是谁用 `ip link show veth-h`（看 `@ifN`）。
- **教训**：命令的**显示输出**和**可引用的标识**是两回事，别整行照抄。

## 9. `ip link add` 和 `ip addr add` 混淆

- **看到什么**：`sudo ip link add 10.200.1.1/24 dev veth-h` → `Error: argument "10.200.1.1/24" is wrong: "dev" not a valid ifname`。
- **为什么**：`ip link add` 期待的是**新网卡的名字**；`10.200.1.1/24` 被当成了网卡名，后面的 `dev` 就变得莫名其妙。
- **怎么修**：`ip addr add 10.200.1.1/24 dev veth-h`。
- **教训**：**link = 网卡（硬件），addr = 号码（IP），route = 路牌（路由）**。

## 10. iptables 漏了 `-A`，报错却指向参数

- **看到什么**：`iptables -t nat POSTROUTING -s … -j MASQUERADE` → `Bad argument \`POSTROUTING'`（自己的 `network.go` 里也犯过同一条）。
- **为什么**：`-t nat` 只是选表，**还必须给一个操作**（`-A` 追加 / `-D` 删除）；少了它，`POSTROUTING` 就成了非法参数。
- **怎么修**：`-t nat -A POSTROUTING …`。
- **教训**：包装函数把**整条命令**打进错误信息里（`strings.Join(args, " ")`），一眼就能看出缺东西——**报错要带上下文**。

## 11. 改了代码没生效：忘了 `git pull` 就重新编译

- **看到什么**：代码已经修好并 push，重编后行为**完全没变**（还是同一条报错）。
- **为什么**：VPS 上的仓库还停在旧提交；`cd xxx && go build` 因为"已经在那个目录里"而 `cd` 失败，后面那条 `go build` 编的是**旧源码**。
- **怎么修**：固定三步排查——① 源码真的改了吗（`git log -1` / `grep 那一行`）② 二进制是新编的吗（`ls -l` 比时间戳）③ 跑的是这个二进制吗（`type`）。
- **教训**：**"我明明改了"** 的头号原因是"跑的不是新代码"；先验证事实，再怀疑逻辑。
