# Phase 2 学习笔记

> Linux 隔离与安全原语。完成于 2026-10-06。

## 一句话

命名空间只是"看得见什么"，**真正把容器关住的是另外三层**：cgroup 管资源、seccomp 管系统调用、netns 管网络。三层各挡一类威胁，而且互相独立失效。

## 关键链条（背下来）

```
容器 = clone(CLONE_NEW*) 出来的进程  +  pivot_root 换根  +  execve 变成目标程序
        ↑ 父进程做：cgroup、接线        ↑ 子进程做：setns → 私有挂载 → 换根 → seccomp → exec
归属： 资源 → cgroup（宿主机视角的文件）    隔离 → namespace（只能在 clone 时设置）
```

**三种"接口"记法**：

| 要管什么 | 接口 |
|---|---|
| namespace | 只能系统调用（`clone` / `unshare` / `setns`）——没有文件接口 |
| cgroup | 就是**文件**（`os.WriteFile` 写 `/sys/fs/cgroup/...`）——你没写一行系统调用 |
| 网络 | `ip` / `iptables` 命令编排（内核里是 netlink 消息） |

## 四个"啊哈"时刻

1. **申请 ≠ 占用**：内存炸弹打印 84 GB，内核说实际 `anon-rss` 只有 100 MB。`memory.max` 管的是**真占的物理页**，不是虚拟地址空间。诊断内存压力永远看 cgroup 账本和内核日志。
2. **seccomp 不可逆，所以只能装最后**：装早了会把自己的 `mount` 初始化挡掉（报 `把 / 设为私有: operation not permitted`）。而且它**每线程**生效——Go 里得先 `LockOSThread`。
3. **`pkts=0` 是 iptables 的测谎仪**：规则存在但包计数器是 0 = 条件从没匹配过。NAT 上不了网那次，一眼就定位到 `-o` 填成了内网口。
4. **同一个 whiteout，两种载体**：tar 层里是 `.wh.<名字>` 空文件（Phase 1 手搓过），文件系统层里是设备号 `0:0` 的字符设备（overlay 的 upper 目录）。**这就是镜像层 = overlay lowerdir 的实感**。

## 交付物

mini-container v2.0（Go，447 行）：`run`（父进程：clone + cgroup + 接线）/ `child`（容器内：setns + pivot_root + seccomp + exec）。三个源文件：`main.go` / `seccomp.go` / `network.go`。

- 资源：`-memory 100M -pids 20` → 容器内 `membomb` 被 OOM 杀，宿主机 `free -h` 不变
- 系统调用：`mount` → `EPERM`（`strace` 实证：初始化 3 次 `mount = 0`，容器内 `mount = -1 EPERM`）
- 网络：容器内 `ping 8.8.8.8` 0% loss；宿主机看不到 `10.200.9.2`；退出后 netns/veth/NAT 全部回收（0/0/0/0）

测试 T2-1 ~ T2-5 全部通过。

## 设计收获（比命令值钱）

**"先建好，再进去"**：一开始让容器自己 `CLONE_NEWNET`，结果是拿到一间**没有网线的空屋子**。改成父进程先把 netns/veth/地址/路由配好，子进程 `setns` 进去——**接线这种活只有宿主机视角的父进程能干**。真 runc 的分工就是这样（`runc init` 是子进程那一侧），CNI 插件做的就是"接线"这一段。
