老陈: 欢迎收听沙盒学习电台，我是老陈。
小林: 我是小林。今天这期，我们来复盘容器运行时进阶这一章，帮你把 Phase 1 的知识点串成一条线。
老陈: 先从最顶层的三个词说起，O C I 的三个规范。镜像规范，运行时规范，分发规范。小林，你用一句话分别说说它们各管什么？
小林: 好。镜像规范管的是，镜像在硬盘上长什么样。运行时规范管的是，容器跑起来时，标准长什么样。分发规范管的是，镜像怎么从仓库拉下来，推上去。
老陈: 对，三权分立。镜像不管运行，运行不管分发。接下来是这一章最核心的一张图，镜像内部的四个结构体加一条引用链。
小林: 四个结构体是，索引文件，清单文件，配置文件，还有镜像层。引用链是，索引指向清单，清单指向配置和镜像层。
老陈: 记住这条链，index 指向 manifest，manifest 再指向 config 和 layers。后面所有工具，pull，解包，运行，都是在顺着这条链走。
小林: 这里有个关键设计，内容寻址。每个文件的名字，就是它内容的哈希值。
老陈: 没错，digest 就是文件名。你改一个字节，名字就全变了。所以改了一层，就得从头重造整条链，偷懒只改一处，只会得到一堆对不上的引用。
小林: 说到层，就得提 whiteout。镜像层是只读的，上层想删掉下层的一个文件，怎么办？
老陈: 上层放一个特殊文件，名字叫点 w h 加文件名，意思就是，这个文件我删了。这就是 whiteout。还有一种，点 w h 点 w h 点 o p q，意思是这个目录被我清空了，下层的东西都别透下来。
小林: 明白了，删不掉就记一笔说删了。下一组，runc，containerd，docker，这三个到底谁干嘛？
老陈: runc 是干脏活的，直接跟内核打交道，创建容器进程。containerd 是经纪人，管镜像，管容器生命周期，对外暴露接口。docker 是门面，用户摸到的命令行，背后调的还是 containerd。
小林: 所以 runc run 和 docker run 的关系是？
老陈: runc 只懂一个 bundle，就是 rootfs 加 config 文件。docker run 背后经过 containerd，最后也是调 runc 干活。runc create 是只创建不启动，runc run 等于创建加启动。
小林: 这一章的实战项目是 mini-oci，自己写了三个子命令，pull，unpack，run。
老陈: pull 是顺着引用链把 blob 拉下来，unpack 是解压 tar 叠成 rootfs，run 是拼出 bundle 丢给 runc。写完这三个，容器运行时这层就没有黑盒了。
小林: 最后聊聊实战里踩过的几个经典坑。第一个，Go 的 select 空分支。
老陈: 对，内存炸弹里写 select 大括号，Go 的死锁检测会直接 panic，报错说所有 goroutine 都睡着了。正确姿势是用信号等待，既不会崩，docker stop 发信号还能体面退出。
小林: 第二个，heredoc 的 E O F 必须顶格。
老陈: 前面多一个空格，shell 就永远等下去，终端卡住不动，命令根本没执行。救法是 Ctrl C，或者干脆别用 heredoc，用 printf 或者编辑器写。
小林: 第三个，skopeo 连不上 docker。
老陈: 在 Colima 下面，docker 的 socket 不在默认位置。关键是 skopeo 不读 docker 的上下文配置，也不用环境变量，必须用专用参数显式指定 socket 地址。
小林: 好，Phase 1 的主线就是这些。四个结构体一条链，内容寻址，whiteout，三者分工，外加亲手写一遍 pull，unpack，run。
